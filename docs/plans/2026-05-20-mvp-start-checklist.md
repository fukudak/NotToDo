# NotToDo MVP 開始前チェックリスト

> **目的:** 実装に入る前に、抜けやすい前提を先に潰しておく。
>
> **方針:** 迷ったらこの順番で確認する。未確定の項目があれば、実装を始める前に止める。

---

## 1. 仕様の確認

- [ ] MVP の目的は明確か
- [ ] 無料 / 有料の差分は機能数制限でよいか
- [ ] ユーザー切り替えはローカル運用から始めるか
- [ ] 本格ログインは後回しでよいか
- [ ] JSON スキーマは `docs/plans/2026-05-20-json-data-schema.md` に揃っているか

---

## 2. 環境の確認

- [ ] Flutter の版を FVM で固定したか
- [ ] Node / Python / CLI の版を mise で固定したか
- [ ] Docker Compose の骨組みを作るか
- [ ] ホスト側で実機デバッグする前提が明確か

---

## 3. データの確認

- [ ] 保存先はローカルでよいか
- [ ] `activeUserId` を使うか
- [ ] `plan` と `maxItems` を持つか
- [ ] `featureFlags` を持つか
- [ ] スキーマバージョン `version` を持つか

---

## 4. 画面の確認

- [ ] リスト画面
- [ ] 編集画面
- [ ] 設定画面
- [ ] 必要なら詳細画面
- [ ] 課金案内画面の導線
- [ ] エラー / 空状態画面

---

## 5. 実装の確認

- [ ] 先に画面骨組みを作る
- [ ] 次にユーザー切り替えを作る
- [ ] 次にローカル保存を作る
- [ ] 次に件数制限を入れる
- [ ] 次にエクスポート / インポートを作る

---

## 6. 完了条件

- [ ] ここにあるチェック項目がすべて埋まっている
- [ ] 実装タスク分解と矛盾していない
- [ ] 計画文書の置き場所が `docs/plans/` で統一されている
