# NotToDo 環境固定ファイルの追加

> **目的:** プロジェクトを開いたときに、どのツールのどの版を使うかを迷わないようにする。
>
> **方針:** 版固定はリポジトリに残す。ホスト側に依存するものは最小限にし、再現性の高いコマンドを優先する。

---

## 1. 実施内容

- `.fvm/fvm_config.json` を追加
- `.mise.toml` を追加
- `docker-compose.yml` を追加
- `Makefile` を追加
- `.env.example` を追加
- `.gitignore` を更新
- `docs/plans/README.md` を更新

---

## 2. 目的に対する狙い

- Flutter 版をプロジェクト単位で固定する
- Node 版をプロジェクト単位で固定する
- Docker でサーバー系の実行環境を分離する
- 開発コマンドの入口を `make` に寄せる

---

## 3. 追加したファイル

### `.fvm/fvm_config.json`
Flutter SDK のバージョンを固定する。

### `.mise.toml`
Node を 22 系に固定する。

### `docker-compose.yml`
ローカル開発用の Bun コンテナ定義。

### `Makefile`
環境確認・起動用の入口。

### `.env.example`
最低限の環境変数例。

---

## 4. 確認したこと

- ホストには `node` はある
- `bun` は未導入だった
- `mise` は未導入だった
- そのため、今回は「版固定ファイルの追加」と「入口ファイルの整備」までを行った

---

## 5. 次の一手

1. `fvm` / `mise` / `bun` の導入方法を決める
2. `make env` の確認を入れる
3. 画面骨組みの実装へ進む
