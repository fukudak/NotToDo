# NotToDo ディレクトリ構成方針

> **目的:** 実装を始めたときに、どのファイルをどこへ置くかを迷わないようにする。
>
> **方針:** 機能別に大きく分け、環境・計画・実装・データを明確に区別する。計画は `docs/plans/`、判断は `docs/adr/` に残す。

---

## 1. ルート構成

```text
NotToDo/
├── client/                  # UI
├── server/                  # API
├── data/                    # ローカル永続データ（git 管理外）
├── docs/                    # 仕様・ADR・計画
│   ├── adr/
│   └── plans/
├── infra/                   # Docker / 開発補助 / 環境定義
├── .fvm/                    # Flutter 版固定
├── .mise.toml               # CLI 版固定
├── docker-compose.yml       # サーバー系の起動定義
├── package.json             # ルートの実行コマンド
└── CLAUDE.md                # プロジェクト方針
```

---

## 2. フォルダの役割

### client/
- 画面
- コンポーネント
- フック
- クライアント側の型

### server/
- API ルーティング
- 永続化ロジック
- 課金判定の接続口

### data/
- 実データ
- バックアップ出力の一時置き場

### docs/
- 仕様
- 計画
- 技術判断

### infra/
- Docker 関連
- モック
- 開発補助スクリプト

---

## 3. 実装時の置き方

- 新しい判断は `docs/adr/`
- 新しい計画は `docs/plans/`
- 一時データは `data/`
- インフラの設定は `infra/`
- UI は `client/`
- サーバーは `server/`

---

## 4. 完了条件

- どこに何を置くかが一目で分かる
- 計画と実装が混ざらない
- 端末環境差があっても構造が崩れない
