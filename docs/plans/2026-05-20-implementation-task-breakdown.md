# NotToDo 実装タスク分解

> **目的:** MVP を「作れる順」に分解し、順番に積み上げるだけで完成まで進められる状態にする。
>
> **方針:** 1 タスクは短く、検証可能で、依存関係が明確な単位にする。計画は増やしても、実装時に迷わないことを最優先にする。

---

## 1. タスク分解の原則

- 1 タスクは小さくする
- 1 タスクで 1 つの判断だけを変える
- 先に土台、後で見た目
- 先に保存、後で便利機能
- 先に無料版の完成、後で有料差分

---

## 2. 実装順

### Task 1: 環境固定ファイルを置く
**目的:** 開発環境の版をプロジェクト内で固定する。

**対象:**
- `.fvm/fvm_config.json` または同等の FVM 設定
- `.mise.toml`
- `docker-compose.yml`

**完了条件:**
- どの版を使うべきかがファイルを見れば分かる

---

### Task 2: MVP の画面骨組みを作る
**目的:** リスト、編集、設定の導線を作る。

**対象:**
- リスト画面
- 編集画面
- 設定画面
- 必要なら詳細画面

**完了条件:**
- 画面遷移が壊れずに見える
- まだデータがなくても起動できる

---

### Task 3: ユーザー切り替えの最小実装を入れる
**目的:** 端末内でユーザーごとの表示を分ける。

**対象:**
- `user_id` の生成
- 現在ユーザーの保持
- ユーザー一覧
- 切り替え

**完了条件:**
- userA と userB の表示が分かれる

---

### Task 4: ローカル保存を実装する
**目的:** やらないことデータを端末内に保存する。

**対象:**
- 項目の追加
- 項目の編集
- 項目の削除
- 完了状態の更新
- 再起動後の復元

**完了条件:**
- アプリを閉じてもデータが残る

---

### Task 5: 件数制限を実装する
**目的:** 無料 / 有料差分の土台を作る。

**対象:**
- `plan` / `maxItems` の取得
- 無料版上限の判定
- 上限到達時の案内
- 有料版の無制限表示

**完了条件:**
- 上限に達したら追加できない
- 有料では制限が変わる

---

### Task 6: エクスポート / インポートを実装する
**目的:** バックアップと移行を可能にする。

**対象:**
- JSON 出力
- JSON 取り込み
- 上書き確認
- ユーザー単位の対象選択

**完了条件:**
- バックアップから復元できる

---

### Task 7: 課金導線を追加する
**目的:** 有料版に進む入口を作る。

**対象:**
- 課金案内画面
- 購入導線
- プラン表示
- 復元導線

**完了条件:**
- 無料と有料の違いが画面で分かる

---

### Task 8: 将来のログイン接続口を作る
**目的:** 後から本格認証を足しやすくする。

**対象:**
- 外部アカウントと `user_id` の対応
- 認証 API の取り込み口
- ログイン未導入でも壊れない構造

**完了条件:**
- ローカル切り替えから本格ログインへ移行しやすい

---

## 3. ドキュメント更新ルール

- 仕様変更があればこの文書を増補する
- 途中で迷ったら、先に短い追記を残す
- 実装が終わったら、対応する計画を更新する

---

## 4. 完了条件

- 実装順が具体的になっている
- 各タスクの完了判定がある
- 課金前提の分岐が土台から明示されている
- この順番で進めれば MVP が組み上がる
